# LifeOS — Obsidian-плагин с ИИ-агентами

> Агенты `day-planner` и `content-pipeline` через **OpenCode CLI + DeepSeek**, прямо из Obsidian: утренний план, чек-ины, итоги дня, контент-конвейер и чат — без выхода из приложения.

Плагин — это «транспорт и UI»: он запускает CLI-агентов `opencode` с рабочим каталогом = ваш vault и показывает результат в заметках/модалках. Вся логика агентов живёт в **markdown-конфигурации внутри vault** (`.opencode/`), поэтому поведение правится правкой файлов, без пересборки плагина.

## Требования

| Что | Требование |
| --- | --- |
| Obsidian | **Desktop** v1.5.0+ (плагин использует `child_process` — мобильные версии не поддерживаются) |
| [OpenCode CLI](https://opencode.ai) | установлен и доступен из терминала (проверка: `opencode --version`) |
| Аккаунт DeepSeek | API-ключ (`sk-...`) с положительным балансом |
| Операционная система | macOS / Linux / Windows (проверено на macOS; для Windows потребуется свой путь к бинарнику) |

## Установка

### Вариант 1. Из релиза (рекомендуется)

1. Скачайте последний релиз с GitHub-страницы репозитория и распакуйте архив — нужны три файла: `main.js`, `manifest.json`, `styles.css`.
2. Скопируйте их в папку плагинов вашего vault:

   ```
   <ваш vault>/.obsidian/plugins/lifeos/
   ```

   Если папки `.obsidian/plugins/lifeos` нет — создайте её. Путь `.obsidian` скрытый: в Finder используйте `Cmd+Shift+.`, либо откройте vault через **Настройки → Сторонние плагины → Просмотреть папку плагинов**.
3. В Obsidian: **Настройки → Сторонние плагины (Community plugins)** → включите «Ограниченный режим» (Restricted mode) при необходимости → нажмите **Обновить (Reload)** рядом со списком плагинов.
4. Включите плагин **LifeOS** переключателем.

> 💡 Альтернатива — плагин [BRAT](https://github.com/TfTHacker/obsidian42-brat): добавьте репозиторий плагина через BRAT и обновляйтесь одной кнопкой.

### Вариант 2. Из исходников (для разработки)

```bash
# 1. Склонировать и установить зависимости
git clone <url-репозитория> && cd Obsidian-life-os
npm install

# 2. Собрать main.js
npm run build

# 3. Скопировать сборку в vault (путь можно переопределить)
LIFEOS_VAULT="/path/to/your/vault" npm run sync
```

Скрипт `npm run sync` копирует `main.js`, `manifest.json`, `styles.css` в `<vault>/.obsidian/plugins/lifeos/`, а канонические шаблоны и конфиг opencode — в подпапку `canonical/` (см. следующий раздел).

Для разработки с автопересборкой: `npm run dev` (watch-режим esbuild).

## Установка конфигурации агентов в vault (`.opencode/`)

Агенты (`day-planner`, `content-pipeline`), их скиллы и провайдер DeepSeek определяются конфигурацией opencode, которая должна лежать **внутри vault**:

```
<ваш vault>/.opencode/
├── opencode.jsonc              # провайдер deepseek + агенты + permissions
├── agent/
│   ├── day-planner.md
│   └── content-pipeline.md
└── skills/
    ├── daily-note-template/SKILL.md
    ├── priority-rules/SKILL.md
    ├── obligations-radar/SKILL.md
    ├── mini-checkin/SKILL.md
    ├── evening-retro/SKILL.md
    ├── content-brief/SKILL.md
    ├── stage-transition/SKILL.md
    ├── multi-format-adapter/SKILL.md
    └── event-recap/SKILL.md
```

Канонические источники лежат в репозитории плагина: [`lifeos-opencode/`](lifeos-opencode/) и [`templates/daily.md`](templates/daily.md). Скопируйте их в vault (один раз, при первом запуске):

```bash
# из каталога репозитория:
cp -R lifeos-opencode/. "<ваш vault>/.opencode/"
mkdir -p "<ваш vault>/4. Архив/Шаблоны"   # путь по умолчанию из настроек
cp templates/daily.md "<ваш vault>/4. Архив/Шаблоны/daily.md"
```

После этого в настройках плагина нажмите **«Установить шаблон дейлика»** (создаст заметку-шаблон с frontmatter `energy`/`content_block`) и проверьте результат кнопкой **«Открыть сегодняшний дейлик»**.

> ⚠️ Убедитесь, что папка `.opencode/` синхронизируется с вашим бэкапом/obsidian-git — это ваша версионируемая «прошивка» агентов.

## Настройка плагина

**Настройки → LifeOS:**

| Поле | Описание |
| --- | --- |
| Путь к бинарнику opencode | Абсолютный путь к `opencode`. Пусто = автоопределение (см. [Решение проблем](#решение-проблем) про PATH) |
| Путь к vault | Рабочий каталог, в котором opencode запускает агентов. Пусто = текущий vault |
| DeepSeek API-ключ | Ключ для opencode CLI и фолбэка чата (подробнее — [Хранение секретов](#хранение-секретов)) |
| Модель агентов | Формат `provider/model`, напр. `deepseek/deepseek-flash` |
| Dry-run | Агенты не редактируют файлы, только предлагают план |
| Сессия на день | Продолжать контекст агента в течение дня через session id |
| Таймаут выполнения (мс) | Максимальное время ответа агента (по умолчанию 300 000) |
| Debug-логи | Выводить stderr opencode в консоль разработчика |
| Шаблон дейлика | Путь к заметке-шаблону дневной записи + кнопки установки/открытия |

## Хранение секретов

В плагине один секрет — **DeepSeek API-ключ**. Он никогда не попадает в git, не записывается в заметки и не сохраняется в конфигурацию `.opencode/`.

### Как ключ попадает в агентов

Механика (см. [`resolveApiKey()`](src/runner/opencodeRunner.ts:64)):

1. **Приоритет 1 — настройки LifeOS.** Если поле «DeepSeek API-ключ» заполнено, используется оно. Ключ сохраняется Obsidian'ом в служебный файл плагина: `<vault>/.obsidian/plugins/lifeos/data.json` (стандартный механизм `saveData`; поле в UI скрыто как пароль, но в файле хранится в открытом виде — см. правила безопасности).
2. **Приоритет 2 — obsidian-ai-providers.** Если поле пусто, плагин автоматически читает ключ из настроек установленного плагина `obsidian-ai-providers`: `<vault>/.obsidian/plugins/ai-providers/data.json` → `providers[]` с `type: "deepseek"` (или `name`, содержащим "deepseek"). Это же хранилище используется для чата.
3. Ключ **передаётся процессу opencode через переменную окружения** `DEEPSEEK_API_KEY` (см. [`runAgent()`](src/runner/opencodeRunner.ts:106)) — только в память дочернего процесса, на время одного запуска, и не записывается ни в какие файлы vault.
4. Конфигурация [`opencode.jsonc`](lifeos-opencode/opencode.jsonc) ссылается на ключ через плейсхолдер `{env:DEEPSEEK_API_KEY}` — сам конфиг секретов не содержит.

### Как ключ попадает в чат

Боковая панель LifeOS Chat (см. [`ChatProvider`](src/chat/chatProvider.ts:22)):

1. **Основной путь** — `obsidian-ai-providers` (настройка «Использовать obsidian-ai-providers» включена по умолчанию): стриминг через SDK плагина, ключ берётся из его настроек. Ключ в настройках LifeOS при этом не требуется.
2. **Фолбэк** — если ai-providers недоступен: прямой вызов `https://api.deepseek.com/chat/completions` с `Authorization: Bearer <apiKey>` из настроек LifeOS.

### Где ключ НЕ хранится

- ❌ не в заметках vault (включая дейлики и заметки `.opencode/`);
- ❌ не в `opencode.jsonc` (только плейсхолдер `{env:DEEPSEEK_API_KEY}`);
- ❌ не в git: `data.json` плагина и ai-providers лежат внутри `.obsidian/`, который не коммитится; убедитесь, что он не попал в синхронизируемые файлы;
- ❌ не в логах: при включённых Debug-логах в консоль выводится только stderr opencode (ключ в него не попадает).

### Правила безопасности

1. **Никогда не вставляйте ключ в заметки** — они могут синхронизироваться в облако и попасть в публичный доступ.
2. **Не коммитьте `.obsidian/`** в публичные репозитории. Если используете obsidian-git — проверьте, что `.obsidian/plugins/**/data.json` не синхронизируется (или добавьте в исключения).
3. Убедитесь, что **папка vault не является публичным репозиторием** — иначе `data.json` с ключом утечёт.
4. **Управление доступом в `.opencode/`**: агентам выданы минимальные права — запись только в свои зоны (`1. Проекты/diary/**` и `1. Проекты/Личный бренд/Посты/**`), `bash: deny`, `webfetch/websearch: deny`. Не расширяйте permissions без необходимости.
5. Если ключ скомпрометирован — отзовите его в кабинете DeepSeek и замените в настройках.

## Решение проблем

**«opencode не найден» / агент не запускается**
Obsidian, запущенный из Finder/Dock, **не наследует PATH терминала**. Плагин проверяет известные пути (`/opt/homebrew/bin/opencode`, `/usr/local/bin/opencode`, `~/bin/opencode`, `~/.local/bin/opencode`), но если opencode установлен в другое место — нажмите **«Определить»** в настройках или впишите путь вручную.

**«Session not found»**
Симптом: при включённой «Сессии на день» первый запуск падает — у opencode 1.18 сессия не создаётся автоматически. Плагин сам повторяет запуск без `-s`. Если не помогает — выключите «Сессию на день».

**«402 Insufficient Balance» / пустые ответы**
Пополните баланс DeepSeek в кабинете. Проверьте ключ в настройках LifeOS или в настройках obsidian-ai-providers (см. [Хранение секретов](#хранение-секретов)).

**Агент пишет не туда / правит лишнее**
Включите **Dry-run** — агент будет только предлагать план. Проверьте permissions в [`opencode.jsonc`](lifeos-opencode/opencode.jsonc): по умолчанию запись разрешена только в `diary/**` и `Посты/**`.

**В чате висит «…» / «Агент думает…» — это зависло?**
Нет, это нормально: перед первым токеном ответа DeepSeek CLI `opencode` стартует и инициализируется (чтение конфига, сетевой запрос) — обычно 10–60 секунд. С версии с индикаторами вы видите таймер «🤖 Агент думает… 0:45» и кнопку «⏹ Отмена», а прогресс-модалка команд из палитры показывает тот же отсчёт. Как только приходит первый токен — статус исчезает и стримится текст. Если таймер зашкаливает за 5 минут (дефолтный таймаут) — появится ошибка; проверьте баланс DeepSeek («402 Insufficient Balance») и ключ.

**Хочу смотреть stderr opencode**
Включите «Debug-логи» и откройте консоль разработчика (`Cmd+Option+I`) — там будет поток stderr процесса, видно этапы инициализации CLI.
